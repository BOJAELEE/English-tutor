# 아침 알림(푸시 알림) 설계

날짜: 2026-07-12
대상: `web/sw.js`, `web/app.js`, `web/index.html`, 신규 `data/kr-holidays.json`, 신규 `.github/workflows/notify.yml`, 신규 `scripts/send-notification.mjs`

## 배경

사용자가 운전 중 영어회화 연습을 하는데, 앱을 매일 여는 걸 잊어버리기 쉬움. 공휴일을 제외한 매일 아침 7시 10분에 "영어회화 연습 시작" 알림을 받고 싶어함.

이 요구사항("앱/브라우저가 꺼져 있어도 정해진 시각에 알림")은 지금까지 이 프로젝트가 유지해온 "완전 정적 사이트(빌드 없음, 서버 없음)" 가정으로는 구현할 수 없다. 브라우저 표준만으로는 앱이 꺼진 상태에서 특정 시각에 알림을 예약 발송할 방법이 없기 때문에(Notification Triggers API는 실험 단계, 폭넓게 지원되지 않음), 실제 동작하는 Web Push를 쓰려면 정해진 시각에 발송을 트리거하는 무언가가 필요하다.

명확화 결과:
- 기존에 배포용으로 쓰고 있는 GitHub Actions를 예약 작업(cron)으로도 활용 — 서버를 직접 운영하지 않고 무료로 스케줄러 확보
- 공휴일 판단은 한국 공휴일 기준, 연도별 데이터를 직접(수동) 관리
- "매일"은 평일만 의미함 (토·일 및 공휴일 모두 제외)
- 알림 탭 시 앱을 열고 바로 오늘의 학습(`runDay()`) 시작

## 1. 아키텍처 & 컴포넌트

```
web/sw.js                          → push 이벤트 리스너(알림 표시) + notificationclick 리스너(앱 열고 자동 시작) 추가
web/app.js                         → "알림 켜기" 버튼(설정 화면) + 구독(subscription) 생성 로직 + ?autostart=1 처리 추가
data/kr-holidays.json (신규)        → 한국 공휴일 날짜 목록, 연도별 수동 관리
.github/workflows/notify.yml (신규) → 평일 아침 7:10(KST) 예약 실행 + 수동 실행(workflow_dispatch) 지원
scripts/send-notification.mjs (신규) → Node.js + web-push 라이브러리로 실제 발송 (GitHub Actions 안에서만 실행되며 로컬 개발엔 영향 없음 — 기존 "빌드 스텝 없음" 원칙은 클라이언트/로컬 개발 기준으로 계속 유지)
```

- **cron 스케줄**: GitHub Actions는 UTC 기준이므로 `10 22 * * 0-4` (UTC 일~목 22:10)로 설정하면 정확히 KST 월~금 07:10에 실행된다.
- **VAPID 키**: 공개키는 클라이언트 코드에 그대로 포함(비밀 아님). 개인키는 GitHub Actions 시크릿(`VAPID_PRIVATE_KEY`)으로만 보관, 저장소에 커밋하지 않는다.
- **구독 정보 저장**: 백엔드가 없으므로 앱이 구독 정보를 자동으로 어딘가에 저장할 방법이 없다. 최초 1회, 사용자가 "알림 켜기"를 누르면 구독 정보(JSON)가 화면에 표시되고, 이를 개발 세션(Claude Code)에 전달하면 `gh secret set`으로 GitHub 시크릿(`PUSH_SUBSCRIPTION`)에 등록하는 1회성 수동 연결로 처리한다. 이후로는 완전 자동.

## 2. 데이터 흐름

**최초 설정 (1회):**
1. 설정 화면에서 "알림 켜기" 버튼 탭 → 브라우저가 알림 권한 요청 → 사용자 허용
2. `sw.js`가 공개 VAPID 키로 푸시 구독 생성 → 화면에 구독 정보(JSON) 표시 + 복사 버튼
3. 사용자가 그 텍스트를 개발 세션에 전달 → `gh secret set`으로 `PUSH_SUBSCRIPTION` 시크릿 등록

**매일 아침 (자동):**
1. GitHub Actions가 KST 07:10(평일)에 실행됨
2. `data/kr-holidays.json`을 확인해 오늘이 공휴일이면 아무것도 하지 않고 종료
3. 공휴일이 아니면 `scripts/send-notification.mjs`가 저장된 구독 정보로 "영어회화 연습 시작" 푸시 발송
4. 폰이 꺼져있거나 앱이 실행 중이 아니어도, 브라우저가 백그라운드에서 푸시를 수신 → `sw.js`의 `push` 리스너가 알림 표시
5. 사용자가 알림 탭 → 앱이 `index.html?autostart=1`로 열림 → `app.js`가 즉시 오늘의 학습(`runDay()`) 시작

**오류 처리:** 발송 실패(예: 구독 만료 — 앱 재설치, 브라우저 데이터 삭제 등) 시 GitHub Actions 실행이 실패로 표시되고, GitHub이 저장소 소유자에게 기본 실패 이메일을 보낸다. 1인 프로젝트이므로 별도 알림 채널은 만들지 않는다.

## 3. 테스트 계획

- `notify.yml`에 `workflow_dispatch`(수동 실행 버튼)를 함께 넣어, 실제 아침 7:10을 기다리지 않고 언제든 강제 실행해 검증 가능하게 한다.
- 공휴일 판별 로직은 순수 함수로 분리해 여러 날짜(공휴일/평일/주말)로 단위 테스트한다.
- 클라이언트 구독 로직(권한 요청 호출, 구독 생성 호출)은 헤드리스 브라우저로 코드 경로 확인.
- 실제 알림이 폰 화면에 표시되는 것 자체는 사용자의 실제 폰에서 최종 1회 확인이 필요하다 (헤드리스 환경에서는 OS 알림 표시까지 확인 불가).

## 범위 밖

- 여러 기기/여러 사용자 구독 지원 (지금은 폰 1대 기준 단일 구독)
- 공휴일 데이터 자동 갱신(공공데이터포털 API 연동) — 연도별 수동 관리로 충분
- 알림 시각을 앱 안에서 사용자가 직접 바꾸는 UI (지금은 07:10 고정)
