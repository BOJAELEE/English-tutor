# 패턴 추가 및 배포 간편화 설계

날짜: 2026-07-11
대상: `data/patterns_raw.txt`, `scripts/parse_patterns.py`, `web/day-tasks.js`, `web/app.js`, `web/index.html`, 신규 `패턴추가.bat` / `scripts/add_patterns.ps1`

## 배경

현재 200패턴/50일 커리큘럼을 다 마친 뒤, 사용자가 새 패턴을 추가해서 계속 학습하고 싶어함. 지금 방식은 텍스트 준비부터 배포까지 전 과정이 Claude Code 세션을 거쳐야 하는데, 사용자는 앞으로 이 과정을 **직접, 대화 없이** 반복하고 싶어함.

명확화 결과:
- 텍스트 파일 준비(패턴 원문 작성)는 본인이 직접 함
- 그 이후 단계(변환·검증·배포)는 **파일 더블클릭 한 번**으로 끝나길 원함

## 1. 패턴 추가 방법

- `data/patterns_raw.txt` 맨 아래에 기존과 동일한 원문 형식으로 새 패턴을 이어 붙인다 (번호는 이전 마지막 패턴 다음부터 연속).
- 새 패턴은 **4개 단위**로 추가한다 (하루 학습량 = 패턴 4개 고정 구조를 유지하기 위함). 4의 배수가 아니면 검증 실패로 안내하고 중단, 기존 데이터는 변경되지 않는다.
- 기존 진행 상황(`localStorage`의 `progress`, 캐시 등)은 전혀 건드리지 않는다. 새 패턴은 항상 기존 마지막 Day 다음부터 이어진다.

## 2. 실행 방식 — `패턴추가.bat`

프로젝트 루트에 `패턴추가.bat`를 두고, 더블클릭하면:

1. `scripts/add_patterns.ps1`(PowerShell)을 실행 — 실제 로직은 여기 구현 (cmd보다 한글 처리가 안정적)
2. `scripts/parse_patterns.py` 실행 — `patterns_raw.txt` → `web/patterns.js` 변환 + 검증
3. 검증 실패 시: 한국어로 원인을 보여주고 창을 닫지 않고 대기 (사용자가 읽고 수정할 시간 확보)
4. 검증 성공 시: `git add` → `git commit`(자동 생성 메시지, 예: "패턴 추가: 201~220번") → `git push`
5. GitHub Actions 배포 완료까지 대기 후 "완료되었습니다. 폰에서 새로고침하세요" 메시지 출력, 대기

## 3. "50일 고정" 가정 제거

패턴 개수에 따라 총 학습일이 자동으로 늘어나도록 변경한다: **총 일수 = 패턴 개수 ÷ 4 (올림)**.

- `web/day-tasks.js`: `TOTAL_DAYS = Math.ceil(PATTERNS.length / 4)` 상수 추가, 전역에서 참조 가능하게 함
- `web/app.js`: 하드코딩된 `50` 두 곳을 `TOTAL_DAYS`로 교체
  - `runDay()`의 `day = Math.min(day + 1, 50)` → `Math.min(day + 1, TOTAL_DAYS)`
  - 설정 저장 핸들러의 `d >= 1 && d <= 50` → `d >= 1 && d <= TOTAL_DAYS`
- `web/index.html`: "현재 Day (1~50)" 라벨과 `input[max="50"]`을 하드코딩하지 않고, 앱 로드 시 `TOTAL_DAYS` 값으로 채운다
- `scripts/parse_patterns.py`: 검증 로직을 "정확히 200개, 1~200 연속"에서 **"4의 배수, 1번부터 빠짐없이 연속"**으로 일반화. 패턴 개수가 몇 개든 동일 스크립트로 검증 가능

## 범위 밖

- 앱 내에서 직접 패턴을 입력/편집하는 UI (사용자가 텍스트 파일 직접 준비를 선호함)
- AI를 이용한 패턴 자동 생성
- 기존 200개 패턴의 내용 변경/재배열

## 검증 계획

- `parse_patterns.py`에 4의 배수가 아닌 개수(예: 202개)를 넣었을 때 명확한 한국어 오류로 실패하는지 확인
- 정상적으로 4개 단위(예: 20개 추가, 총 220개)를 넣었을 때 `TOTAL_DAYS`가 55로 올바르게 계산되는지 확인
- `패턴추가.bat` 더블클릭 시나리오를 헤드리스로 재현 가능한 범위까지 자동 검증(PowerShell 스크립트 로직 자체는 직접 실행해서 확인), 실제 더블클릭 동작은 사용자가 최종 확인
