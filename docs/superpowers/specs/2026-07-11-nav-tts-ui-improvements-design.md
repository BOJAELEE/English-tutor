# 학습 화면 개선: 이전 탐색, 자연스러운 음성, 텍스트 계층, 위치 복원

날짜: 2026-07-11
대상: `web/app.js`, `web/index.html`, `web/style.css`
현재 배포 버전: v6

## 배경

사용자가 실제 운전 중 사용해보면서 4가지 개선 요청:

1. 학습 화면에 "이전"(뒤로가기) 버튼 추가 — 현재는 일시정지/건너뛰기/종료만 있음
2. 한국어 음성(TTS)이 로봇처럼 뚝뚝 끊김 — 문구가 아니라 목소리 자체 문제 (명확화 완료)
3. 상태 화면 둘째줄(status-sub) 글씨가 작음, 첫째줄과 시각적으로 구분되지 않음
4. 건너뛰기/이전으로 여러 번 이동하다 앱을 꺼도, 다음에 열었을 때 정확히 마지막 위치에서 재개

1번과 4번은 서로 얽혀 있어 위치 추적 아키텍처를 함께 바꿔야 한다. 브레인스토밍 중 사용자가 "이전"의 범위를 세션 경계뿐 아니라 **Day 경계까지** 자유롭게 넘나들 수 있어야 한다고 확장했다 (예: Day 10을 막 시작했을 때 "이전"을 누르면 Day 9의 마지막 문제로 이동).

## 1. 위치 추적 아키텍처

### 데이터 모델 변경

`LS.progress`: `{day, session, index}` → **`{day, pos}`**

- `pos`는 "오늘(해당 day)의 할 일 리스트"에서 몇 번째 문제인지를 가리키는 0-based 인덱스
- 세션1(패턴연습)~세션4(전체복습)를 순서대로 이어붙인 하나의 평평한 리스트로 취급
- Day 1: 세션1(12) + 세션2(4) = 16개
- Day 2 이상: 세션1(12) + 세션2(4) + 세션3(4) + 세션4(2) = 22개
- 각 태스크에는 화면 상단 표시용 `sessionName`이 태그로 붙음 (기존 `buildSessions()`의 세션 이름을 재사용)

### 이동 규칙

| 상황 | 동작 |
|---|---|
| 이전, pos > 0 | 같은 day 안에서 `pos - 1` |
| 이전, pos = 0, day > 1 | `day - 1`로 이동, 그 날짜의 마지막 문제(`buildDayTasks(day-1).length - 1`)로 |
| 이전, pos = 0, day = 1 | 이동 없음. "지금이 처음이에요" 음성 안내 후 대기 |
| 건너뛰기 | `pos + 1`. 오늘 마지막 문제였다면 기존 로직대로 `day + 1, pos: 0`으로 자동 진행 (하루 완료 처리) |
| 정상 완료 (교정까지 다 마침) | 건너뛰기와 동일하게 `pos + 1` |

**주의**: 건너뛰기는 오늘 리스트를 벗어나 내일로 미리 넘어가지 않는다 (day 증가는 "오늘 전체 완료" 시에만). 반대로 이전은 자유롭게 과거 day를 넘나든다 — 이미 배운 내용을 복습하는 것이라 커리큘럼 진행 속도에 영향을 주지 않기 때문.

### 저장 시점

`pos` 또는 `day`가 바뀔 때마다 **즉시** `localStorage`에 저장한다 (기존에는 문제를 완전히 끝내야만 저장됨). 이전/건너뛰기로 이동하는 도중 앱을 강제 종료해도 마지막으로 표시하던 문제로 정확히 복원된다.

**중요한 설계 결정**: 별도의 "커리큘럼 진도"와 "마지막 화면 위치"를 나누지 않는다. `{day, pos}` 하나가 곧 "지금 화면에 보이는 위치"이자 "다음에 열었을 때 재개할 위치"다. 즉, Day 10을 학습하다 "이전"으로 Day 9를 복습하던 중 앱을 끄면, 다음에 열었을 때 홈 화면은 "Day 9"로 표시되고 그 지점부터 재개된다 (Day 10으로 자동 복귀하지 않음). 사용자가 요청한 "마지막 위치"를 문자 그대로 구현한 것이며, 다시 Day 10으로 가려면 건너뛰기로 앞으로 이동하면 된다.

### 기존 버그 동시 수정

세션4(전체 복습)는 지금까지 배운 패턴 중 2개를 무작위로 뽑는다. 현재 코드는 `runDay()`를 호출할 때마다 새로 뽑기 때문에, 뒤로 갔다가 다시 오면 **다른 문제가 나온다**. 이전/건너뛰기 기능이 생기면 이 문제가 훨씬 자주 드러나므로 이번에 함께 고친다: 날짜별로 세션4 랜덤 선택 결과를 `localStorage`에 한 번 저장해두고, 같은 날짜를 다시 계산할 때는 저장된 값을 재사용한다.

### 기존 데이터 마이그레이션

이미 Day 1을 진행 중인 사용자가 있으므로, 앱 로드 시 `{day, session, index}` 형식이 감지되면 세션별 문제 개수를 누적 합산해 `pos`로 변환한다: `pos = sum(sessions[0..session-1].length) + index`. 변환 후 새 형식으로 덮어쓴다.

## 2. 화면 버튼 배치

버튼이 3개→4개(이전·일시정지·건너뛰기·종료)로 늘어나므로, 운전 중 안전하게 누를 수 있도록 한 줄 배치를 2행 2열로 바꾼다:

```
[이전]     [건너뛰기]   ← 이동(탐색) 묶음
[일시정지]  [종료]      ← 제어 묶음
```

- 각 버튼은 기존과 동일하거나 더 큰 터치 영역 확보 (4열보다 2열이 버튼 폭이 넓음)
- Day 1의 첫 문제(더 갈 곳 없음)에서는 "이전" 버튼을 시각적으로 비활성화 표시

## 3. 한국어 음성(TTS) 자연스러움

### 원인

`pickVoice()`가 `v.localService`(기기 내장 오프라인 음성)를 **명시적으로 우선** 선택하고 있다. Windows/Android 기본 내장 한국어 음성은 억양이 부자연스럽고 로봇처럼 들리는 경우가 많다.

### 해결책

1. **자동 선택 순서 반전**: 네트워크(온라인, `localService === false`) 음성이 있으면 우선 사용, 없을 때만 내장 음성으로 폴백. 한국어·영어 둘 다 동일 로직 적용 (같은 코드 경로 재사용, 영어도 잠재적으로 더 나은 음성을 자동으로 얻는 효과).
2. **설정 화면에 음성 선택 UI 추가**: 기기마다 설치된 음성 품질이 다르므로 자동 선택만으로는 보장 못 한다. 한국어/영어 각각 사용 가능한 음성 목록을 드롭다운으로 보여주고, **"미리듣기"** 버튼으로 샘플 문장을 들어본 뒤 고를 수 있게 한다. 선택하면 `localStorage`에 저장되어 이후 계속 그 음성을 사용한다 (자동 선택 로직보다 우선).

## 4. 상태 텍스트 첫째줄·둘째줄 구분

브라우저 목업에서 사용자가 **B안**을 선택함:

- 첫째줄(`#status-main`): 기존 그대로 — 흰색(`#eef0f6`), 24px, 굵게
- 둘째줄(`#status-sub`): 22px로 확대(기존 17px), 색상을 초록 강조색(`#6ee7a0`, 기존 마이크 표시와 동일 색상으로 일관성 유지)으로 변경, `font-weight: 600`

## 범위 밖 (하지 않는 것)

- 화면에 나오는 한국어 문구 자체를 다듬는 작업 (사용자가 "음성만" 문제라고 명확히 확인함)
- "건너뛰기"가 오늘 리스트를 넘어 내일로 미리 진입하는 기능 (요청되지 않음, 커리큘럼 페이싱 보호)
- Day 51 이상이나 Day 0 이하로의 이동 (기존처럼 1~50 범위로 clamp)

## 검증 계획

- 새 Chromium(Playwright, 로컬 설치됨)으로 headless 렌더링 검증: 홈 화면, 설정 화면(음성 선택 포함), 학습 화면(2x2 버튼) 정상 렌더 확인
- 수동 시나리오 점검(코드 리뷰 기반, 실제 음성 상호작용은 자동화 어려움):
  - Day 1 pos 0에서 "이전" → 이동 없음 확인
  - pos > 0에서 "이전" → pos-1 확인
  - Day 2 pos 0에서 "이전" → Day 1 마지막 문제로 이동 확인
  - "건너뛰기"를 오늘 마지막 문제에서 누르면 다음 날로 자동 진행 확인
  - 기존 `{day, session, index}` 형식 저장값 → `{day, pos}`로 정상 마이그레이션 확인
  - 세션4 랜덤 복습이 앞뒤 이동해도 같은 문제로 고정되는지 확인
- 배포 후 버전 배지 v6 → v7로 올려 캐시 갱신 확인
